# blurface — бот для размытия лиц на видео

Telegram-бот и CLI-утилита, которые принимают видео, автоматически находят
все лица в каждом кадре и возвращают видео с размытыми лицами, сохраняя
исходное разрешение, ориентацию, частоту кадров, длительность и аудиодорожку.

Работает локально на Windows 11, без платных сервисов и облака.
Детекция лиц — YuNet (OpenCV, лицензия MIT), кодирование — FFmpeg:
на вашей NVIDIA-карте используется аппаратный кодировщик NVENC,
при недоступности автоматически — libx264 (CPU).

> ⚠️ Размытие — инструмент визуального сокрытия лиц, а не криптографическая
> гарантия анонимности. Не обещает абсолютной невозможности восстановления.

## Как это работает

1. `ffprobe` читает параметры видео (разрешение с учётом rotation metadata,
   fps, длительность, аудио).
2. FFmpeg декодирует кадры **потоково** в пайп (autorotate — кадры приходят
   уже в правильной ориентации; память не растёт даже на длинных видео).
3. YuNet ищет лица на каждом кадре в 2 масштабах: основной проход на
   уменьшенной копии (длинная сторона ≤ 960 px) и дополнительный ×0.5 —
   так находятся и мелкие лица, и крупные планы (модель видит лица
   ~10–300 px в масштабе входа). Дубли объединяются NMS.
4. Области лиц расширяются на настраиваемый запас (FACE_PADDING) и
   размываются (normal / strong / pixelate).
5. FFmpeg кодирует кадры обратно (NVENC или libx264, H.264, качество
   CQ/CRF), аудио копируется без перекодирования (AAC — если копирование
   невозможно), `+faststart` для mp4.
6. Результат проверяется ffprobe: разрешение, длительность, аудио, полная
   декодируемость (для видео короче `VERIFY_MAX_DURATION_SEC`).

## 1. Установка

### Python

Установите Python 3.10+ (проверено на 3.13) с <https://www.python.org/downloads/>
(при установке отметьте «Add python.exe to PATH»). Проверка:

```powershell
python --version
```

### FFmpeg

В проект уже положен portable FFmpeg в `tools\bin` (ffmpeg.exe, ffprobe.exe) —
при наличии он используется автоматически. Если хотите системный FFmpeg:
`winget install Gyan.FFmpeg` (перезапустите терминал после установки).
Проверка:

```powershell
ffmpeg -version
```

### Настройка окружения (один раз)

В PowerShell в папке проекта:

```powershell
.\setup.bat
```

Скрипт создаст виртуальное окружение `.venv`, установит зависимости,
создаст `.env` из примера и запустит проверку окружения.

### Проверка окружения (Python, FFmpeg, GPU, модель)

```powershell
python main.py check
```

или `.\run.bat check`. Ожидаемый вид (для RTX 4060):

```
[OK] Python 3.13.14
[OK] OpenCV 4.14.0, NumPy 2.5.3
[OK] Модель YuNet: ...models\face_yunet_2023mar.onnx
[OK] ffmpeg: ...tools\bin\ffmpeg.exe
[OK] GPU-кодирование NVENC доступно (H.264 через видеокарту)
[WARN] Токен Telegram-бота не задан — локальный режим (process) работает и без него
[OK] Каталог временных файлов доступен: ...tmp
```

Если NVENC показывает `[WARN]` — не страшно: бот/CLI автоматически
переключится на libx264 (CPU). GPU используется только для кодирования;
детекция YuNet идёт на CPU и быстрая (~10–20 мс/кадр).

## 2. Локальная обработка своего видео (без Telegram)

Положите видео в любую папку (например, `D:\blurface\myvideo.mp4`) и выполните:

```powershell
.\run.bat process --input myvideo.mp4 --output myvideo_blurred.mp4
```

Команда выведет исходное/итоговое разрешение, длительность, число обработанных
кадров, число найденных лиц, режим вычислений (GPU/CPU), время работы и путь
к итоговому файлу. Проверено на этой машине: 1080p/30fps/10 c со звуком —
18 с обработки, 300/300 кадров с найденным лицом, NVENC.

Дополнительные параметры команды:

```powershell
python main.py process --input in.mp4 --output out.mp4 `
    --mode pixelate --strength 1.5 --padding 0.4 --encoder x264 --force
```

* `--mode` — `normal` | `strong` | `pixelate` (по умолчанию `strong` из .env);
* `--strength` — сила размытия (множитель);
* `--padding` — запас вокруг лица (доля стороны бокса);
* `--encoder` — принудительно `nvenc` | `x264` (по умолчанию авто);
* `--force` — перезаписать существующий выходной файл.

Синтетические видео для экспериментов (создаются локально, без скачивания):

```powershell
python make_test_video.py --dir tests_data
```

## 3. Telegram-бот

1. В Telegram найдите **@BotFather**, отправьте `/newbot`, выберите имя и
   username бота. BotFather выдаст токен вида `1234567890:AA...`.
2. Впишите токен в файл `.env`:

```
TELEGRAM_BOT_TOKEN=1234567890:AA...
```

3. Запустите бота:

```powershell
.\run.bat bot
```

4. Откройте своего бота в Telegram, отправьте ему видео (как видео или как
   документ MP4/MOV/MKV) — он ответит сообщениями о статусе (скачивание →
   очередь → обработка с процентами → отправка) и вернёт готовое видео.

Ограничения Telegram Bot API (учтены в коде, настраиваются в `.env`):
* скачивание файлов — до 20 МБ (`MAX_INPUT_SIZE_MB=19`);
* отправка — до 50 МБ (`MAX_SEND_SIZE_MB=50`).
* Несколько пользователей могут прислать видео одновременно — задания
  обрабатываются по очереди (`MAX_PARALLEL_JOBS=1`), компьютер не перегружается.

### 3.1. Локальный Bot API сервер (обход лимитов 20/50 МБ)

Облачный Bot API жёстко ограничивает скачивание 20 МБ и отправку 50 МБ. Чтобы
принимать оригиналы с телефона (1080p/4K, до ~2 ГБ) без сжатия, поднимите
self-hosted **Telegram Bot API server** в Docker (готовый `docker-compose.yml`):

1. Получите `api_id` и `api_hash` на <https://my.telegram.org> →
   «API development tools».
2. Впишите их в `.env`:

```
TELEGRAM_API_ID=1234567
TELEGRAM_API_HASH=abcdef0123456789abcdef0123456789
```

3. Запустите сервер:

```powershell
docker compose up -d
```

4. Один раз отключите бота от облачного API (иначе сервер не примет токен):

```powershell
python tools/local_api.py logout
```

   > ⚠️ После этого облачный API перестанет отвечать на этот токен; обратный
   > переход занимает ~10 минут.

5. В `.env` раскомментируйте строку:

```
TELEGRAM_API_BASE=http://localhost:8081
```

6. Перезапустите бота. Лимиты 19/50 МБ поднимутся автоматически до
   1900/1900 МБ (если не задавали их вручную), файлы качаются с локального
   сервера.

Проверка состояния: `python tools/local_api.py status`.

Технические детали:

* контейнер слушает только `127.0.0.1:8081` (наружу не публикуется);
* данные сервера лежат в каталоге `tg-api-data` рядом с проектом;
* бот качает файлы через HTTP-выдачу сервера, при неудаче — читает том
  напрямую (`TELEGRAM_LOCAL_FILES_DIR` / `TELEGRAM_SERVER_FILES_PREFIX`);
* сервер должен работать, пока работает бот; остановить: `docker compose down`.

> ⚠️ Локальный сервер подключается к Telegram **напрямую по MTProto**
> (порт 443, адреса `149.154.x.x`). Если в вашей сети MTProto блокируется
> (доступ к Telegram работает только через VPN/прокси), сервер не сможет
> авторизоваться — тогда оставайтесь в облачном режиме с лимитами 20/50 МБ.

## 4. Автоматические тесты

```powershell
.\run.bat -m pytest tests -v
```

(или активировав venv: `python -m pytest tests -v`)

40 тестов: видео без лиц, с одним/двумя/движущимся лицом, со звуком и без,
1280×720, файл с rotation metadata, повреждённые файлы, очистка временных
файлов, сохранение разрешения/длительности/аудио, фактическое изменение
области лица, лимиты длительности, режимы размытия и др. Все тестовые видео
генерируются кодом (синтетические «лица» рисуются программно, детектируются
YuNet — реальные фото людей не скачиваются).

## 5. Настройки (файл .env)

Все параметры с разумными значениями по умолчанию — см. `.env.example`:
токен, лимиты размера/длительности, режим и сила размытия, запас вокруг
лица, параметры детекции (порог, масштабы), выбор энкодера и качество
кодирования, число параллельных задач, каталог временных файлов.
Менять код для смены режима не нужно — только `.env` или флаги CLI.

Примеры:

* сильнее размытие: `BLUR_STRENGTH=1.5` или `BLUR_MODE=pixelate`;
* больше запас вокруг лица: `FACE_PADDING=0.4`;
* лучше качество результата: `NVENC_CQ=20` (GPU) / `X264_CRF=16` (CPU);
* детекция мельче/крупнее лица: `DET_MAX_SIDE=1280` + `DET_SCALES=1.0,0.5`;
* не проверять результат повторным декодированием: `VERIFY_MAX_DURATION_SEC=0`.

## 6. Устранение неполадок

| Проблема | Решение |
|---|---|
| `FFmpeg не найден` | Проверьте `tools\bin\ffmpeg.exe`, либо `winget install Gyan.FFmpeg`, либо укажите `FFMPEG_PATH=` в `.env` |
| `Driver does not support the required nvenc API version` | Обновите драйвер NVIDIA или поставьте `ENCODER=x264` |
| `[WARN] NVENC недоступен` | Не ошибка: используется libx264 (CPU) |
| Бот: `Файл слишком большой … 20 МБ` | Ограничение скачивания Bot API. Обрабатывайте такие файлы локально (`python main.py process …`) или поднимите свой local Bot API server |
| Результат > 50 МБ и не отправляется | Снизьте длительность/разрешение видео или обработайте локально |
| Кириллица в консоли выглядит «кракозябрами» | `chcp 65001` в консоли или запуск `python -X utf8 …` |
| `Модель YuNet не найдена` | Скачайте `face_yunet_2023mar.onnx` в `models\` (ссылки: opencv_zoo / зеркало opencv/face_detection_yunet на Hugging Face, лицензия MIT) |
| Видео > 10 минут отклоняется | Поднимите `MAX_DURATION_SEC` в `.env` |

## 7. Технические ограничения (честно)

* Перекодирование видео неизбежно меняет пиксели — качество «визуально близкое»
  (CRF 18 / CQ 23), но не побайтово идентичное; 10-битные/HDR исходники
  кодируются в 8-битный H.264 yuv420p для максимальной совместимости.
* Видео с переменной частотой кадров (VFR) обрабатывается всеми кадрами, но
  итог кодируется с постоянной частотой = средняя частота исходника —
  суммарная длительность и синхронизация аудио сохраняются, микротайминги
  отдельных кадров нормализуются.
* YuNet находит лица примерно от 15–20 px и до очень крупных (благодаря
  мульти-масштабу), но может пропускать лица в сильном ракурсе (профиль,
  затылок), при экстремальном освещении или сильно обрезанные кадром.
* Видеозаметки (round video notes) Telegram бот принимает как обычные
  видео-файлы, но отдельного «кружочкового» формата не возвращает.
* Аудио копируется без перекодирования; если кодек несовместим с MP4
  (например PCM), перекодируется в AAC 192 kbps.
